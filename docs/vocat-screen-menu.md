# VoCat v1.2 屏幕和触屏菜单

本轮在 YMOS C 服务结构中增加基础屏幕界面，不引入 XChatbot 的 C++ 应用框架。
平台 URL、语音鉴权、预录音、取消协议和 60 秒静默策略沿用原有实现。
HTTP 设备握手与 MQTT 仍未合入；UI 使用业务快照，便于后续增加平台认证状态。

## 操作

| 场景/操作 | 行为 |
| --- | --- |
| 首页底部 60 px 区域向上滑动至少 60 px | 设置菜单从底部向上滑入，约 250 ms |
| 菜单下滑或点返回 | 菜单向下收起并回到首页；不会开始或打断对话 |
| 待唤醒时轻触首页 | 跳过唤醒词，按现有流程连接/认证 WebSocket；眼睛变为聆听动画后提问 |
| 回答播放时轻触首页 | 手动取消旧回答，保护预录音，取消确认后恢复上传 |
| 聆听中轻触首页 | 结束当前对话，停止上传、关闭 WebSocket，回到等待唤醒；Wi-Fi 保持连接 |
| 取消等待阶段轻触首页（画面已显示聆听） | 同样结束对话并回到待机；迟到的取消确认不会恢复监听 |
| 正在连接时重复轻触 | 现有会话意图合并重复操作 |
| 音量 - / + | 每次变化 5；0..100，可静音 |
| 亮度 - / + | 每次变化 10%；10..100%，避免误调全黑 |
| 当前网络 | 从实际连接 AP 读取 SSID；未连接/正在连接单独显示，长名称滚动 |
| 进入配网 → 确认 | 结束当前对话，打开无密码热点，显示真实热点名和网页 URL |
| 配网页点退出配网 | 关闭 AP，尝试连接保存的网络 |
| BOOT 长按 3 秒 | 继续保留硬件配网入口 |

设置页显示与点击采用同一组矩形；手势在松手时最多提交一次。
首页和菜单使用独立容器，切换时移动整个菜单，文字和按钮一起移动。
正常上滑/下滑过渡采用 20fps、250 ms 的减速动画；配网页由业务状态直接切换，不等待动画。
过渡期间不处理按钮/首页点击，起止均作废旧手势，避免移动中的按钮和背景首页被误点。
滑动后回到原点不视为轻触。菜单不把未命中的点击传给首页。
配网页不能通过下滑隐藏，避免屏幕显示首页但实际仍处于 AP 模式。
触摸读取失败丢弃手势，避免瞬时 NACK 被误判为点击；屏幕或触摸初始化失败时保留语音和 BOOT。
手动待机复用 `end_conversation()`，清除会话意图、重试期限和本轮音频缓存；
恢复本地唤醒词检测，可再次说唤醒词或轻触首页开始新对话。这里的待机不是关机或深度睡眠。

首页使用原 XChatbot VoCat 的 EAF 双眼动画，不显示品牌标题、操作引导或常规会话状态文字。
启动、连接、离线和错误仍显示必要文字；打开菜单的上滑手势仍有效。

| 业务状态 | 动画 |
| --- | --- |
| 等待唤醒 | 原版 `neutral.eaf` 双眼循环动画 |
| 聆听中 | 双眼基础动画，顶部显示 `listen.eaf` 动态状态条 |
| 等待回答 | `confused.eaf` 思考动画 |
| 正在回答 | 双眼基础动画，底部显示动态状态条 |
| 正在打断 | 直接显示聆听画面，取消确认后继续同一动画，不播放中间画面 |

每只眼使用 125×160 px 原图区域，右眼水平镜像；保留原版轮廓/颜色/帧序列。
只映射设备状态，不加载开心/难过等情绪，不依赖平台下发表情。
UI 在比较状态前把 `CANCELLING` 映射为 `LISTENING`，去掉独立眨眼/暂停符号；
业务取消确认与音频保护流程不依赖动画，不会因画面提前显示监听而提前结束。
“等待回答”和“正在回答”沿用音频模块实际输出状态区分；动态状态条仅是状态示意，
不采集实时音量，也不参与打断判断。动画从 Flash 只读映射，使用小型 C RLE 解码器，
不依赖 SD 卡或联网下载；资源/许可证记录见 `assets/face/README.md`。
配网页显示文字连接步骤和 URL；本轮未增加二维码。

## 配置保存

- 音量继续使用 `korvo_cfg/volume`，有效记录优先，没有有效记录默认 40。
- 亮度新增 `korvo_cfg/brightness`，10..100，有效记录优先，否则默认 70。
- 调节立即生效，停止约 1.5 秒后合并写入 NVS；失败 5 秒后重试。
- 刚调节完立即断电，最后一次修改可能未保存；菜单已移除“设置自动保存”文案，保存逻辑继续生效。
- 增加亮度不迁移/擦除分区，也不覆盖 Wi-Fi、设备 ID 或 Token。

## 模块与并发

| 文件 | 职责 |
| --- | --- |
| `board_config.h` / `board_service.*` | 引脚和共享 I2C0 所有权 |
| `display_panel_init.h` | 已运行 VoCat 实现的 ST77916 厂商初始化指令 |
| `display_service.*` | QSPI、背光 PWM、LVGL flush 和图形分配器 |
| `touch_service.*` | CST816S 中断/读点、异常取消；借用 I2C0 |
| `ui_policy.h` | 纯 C 手势、命中区域、亮度规则，供生产和测试共用 |
| `ui_service.*` | 首页/菜单/确认/配网页面；唯一 LVGL 调用任务 |
| `ui_face.*` | 首页表情状态映射、20fps 节拍、双眼镜像、LVGL 图像对象；仅由 UI 任务调用 |
| `ui_animation.*` | 纯 C 的资源包/EAF 校验与 RLE 解码，无动态分配；不访问业务状态 |
| `ui_face_assets.*` | 只读映射 `ui_assets` 分区，管理映射生命周期 |
| `assets/face/`、`scripts/generate_face_assets.py` | 四个固定资源、校验清单与构建时打包 |
| `app_main.c` | UI 动作事件、音量/亮度保存、业务状态到显示快照的映射 |
| `wifi_service.*` / `provisioning_service.*` | 实际 SSID、AP 名称和 URL 的只读查询 |

UI 任务 priority 2、core 0、6144 字节栈；循环中至少让出 10 ms。触摸任务 priority 3、core 0、
3072 字节栈，有中断或按住时才读 I2C，按住期间最多间隔 20 ms 补充采样。
完整手势放入容量 8 的队列；满时丢弃新动作，页面代次过滤旧动作，避免跨页面误触。
触摸采样独立于画面绘制，整屏刷新时仍可读点；共享总线由 IDF I2C 驱动串行访问。
主任务每 150 ms 发布按值复制的快照到容量 1 的覆盖队列。菜单只在状态/页面变化时更新对象；
长 SSID 使用 LVGL 滚动动画。触摸只发布无 payload 的动作事件，避免临时指针生命周期问题。
菜单过渡在同一个 UI 循环按单调时间推进，忙时跳过错过的位置，不追帧；无需额外任务或菜单快照。
过渡期间保留首页作背景并暂停表情解码；正常页面停稳后恢复原有表情/菜单刷新规则。
屏幕硬件方向、DMA 缓冲和触摸坐标不变，仅增加两个页面容器及首页两个文字对象组，分配在 PSRAM。
首页表情以 20fps（50 ms）时间轴选帧，忙时跳过错过的帧，不积压补播；非首页暂停解码。
LVGL 失效区域刷新检查周期为 10 ms，避免默认 40 ms 刷新周期与 50 ms 帧节拍错位。
仍只有原 UI 任务拥有 LCD；没有 Emote/GFX 绘制线程。每帧重用 89,200 字节 PSRAM
（两个 125×160 RGB565 眼睛缓冲 + 一个 100×46 状态条）。显示服务另持有一个完整屏幕缓冲，见下文。
首次显示时校验 486,084 字节资源包；校验/内存失败时显示静态眼睛，保留菜单及语音。
实际帧率取决于音频、网络、解码和 DMA 并发负载，目标 20fps 需实板测量。
进入配网、音频取消、Codec 调节和 NVS 写入由现有主任务执行，不持有绘图锁等待网络。

图形对象分配到 PSRAM，不在分配失败时回退抢占内部堆。显示使用单个
360×360×2=259,200 字节（约 253 KiB）的 PSRAM 帧缓冲，仅供 CPU 绘图和读取。
LVGL 使用 FULL 模式：有画面变化时先画完整帧，再交给显示服务发送；静止菜单不会每 10 ms 重刷。
旧版 10 行缓冲在大面积移动时会交替绘制和发送 36 个条带，容易看到分块、新旧位置混合。
新方案取消这种绘图/传输交替，完整画面合成后才开始拷贝/传输。
40 MHz QSPI 单帧纯像素传输理论约 13 ms，实际还包含拷贝、窗口指令及调度开销。
这是缩短分裂画面的刷新窗口，不是硬件垂直同步：当前没有配置 TE 同步，仍须实板检查残余撕裂。

实际发送使用单个 360×20×2=14,400 字节内部 DMA 缓冲，整帧分 18 段传输。
CPU 先从已完成的 PSRAM 帧拷贝一段到内部 RAM，并只在中转缓冲内转换 RGB565 字节序；
等待该段 DMA 完成后才覆盖缓冲并发送下一段。过程中不重新绘制菜单，所以所有段来自同一帧。
SPI 总线最大传输配置与中转缓冲容量一致，DMA 指针始终指向内部 RAM，
`psram_dma_direct` 明确关闭；不让驱动逐帧临时分配中转内存。
帧缓冲和 DMA 缓冲只在初始化时申请，失败回收并返回；PSRAM 分配不回退到内部 RAM。
相对最早的 7200 字节内部绘图缓冲，新增约 7200 字节固定内部 RAM，另有少量 DMA 描述符。
FULL 模式会增加小范围动画的绘图/传输量，20fps 时像素数据约 5.18 MB/s，
需验收音频/网络并发下的实际帧率、PSRAM 带宽及内部堆余量。
LVGL 9.5.0、ST77916 2.0.2 固定版本，保持原 esp-dl 3.3.13。
DMA 完成通过信号量通知 UI，等待期间让出 CPU；整帧发送完才通知 LVGL 刷新结束。
单段完成等待上限 100 ms；提交报错或等待超时后，记录故障并停止继续向该 LCD IO 提交。
超时后的 DMA 缓冲保留且不再写入，避免覆盖仍可能在途的数据；迟到的完成通知不解除故障。
LVGL 源帧未交给 DMA，故障时仍能释放本次 LVGL 刷新，不将 UI 任务永久卡在完成等待上。
恢复显示需重启；`display_service_deinit()` 仅用于启动失败回收，不是运行中的驱动恢复接口。
HTTP 握手后续移植时仍需实测 TLS/音频/绘图并发的内部堆峰值。

2026-11-05 实板回归曾发现：启用 PSRAM 直接 DMA 后，每次启动均报
`DMA TX underflow detected`，随后 `recycle spi transactions failed` 和 `ESP_ERR_INVALID_STATE`，
导致花屏及显示停止。该路径已撤掉；主机图像测试只能验证像素/逻辑，无法证明外部 RAM DMA 带宽充足。

## 字体

菜单字体来自思源黑体，20 px，ASCII 加界面中文子集，许可证为旁边的 SIL OFL 文件。
屏幕初始化表和手势规则参考 XiaoZhi VoCat 实现，保留的 MIT 许可证见 `docs/third-party/xiaozhi-LICENSE.txt`。
常见中文 SSID 由 LVGL 自带 16 px CJK 字库补充，罕见字/emoji 可能显示占位符，不影响连接。
修改中文界面文字后运行 `python scripts/generate_ui_font.py` 再编译；普通构建不需要 Node.js。

## 验证

主机测试 `tests/ui_policy_checks.c` 直接调用生产规则，覆盖手势、重复松手、回滑、菜单点击隔离、
坐标边界、亮度恢复和限幅。可用本机 C 编译器构建运行。

安装 TCC 后可运行 `python scripts/check_ui.py --cc <tcc可执行文件路径>`：同时编译生产
`ui_service.c` 和 LVGL，以模拟的 RTOS/LCD 传输检查动作路由，输出四页离屏渲染到
`work/ui-checks/`。测试替身仅位于 `tests/ui_host/`，不参与固件构建；不模拟真实触控和音频时序。
加 `--animation-frames` 可导出五种状态各 100 帧（50 ms/帧）。测试执行生产绘制函数，确认图像随时间变化、
菜单不被隐藏动画覆盖、动画不产生对话/配置动作、资源缺失仍可操作菜单。
同时比较完整的监听/取消画面序列，确认播放转取消时立即显示监听，取消确认到达后不重启动画。
菜单回归验证上滑时上沿从 y=360 向 y=0 移动、下滑返回方向相反、首次不先从顶部出现菜单、
未覆盖区域保留首页、过渡点击隔离、返回按钮动画，以及配网可立即覆盖未完成的滑入/滑出。
测试额外输出 `menu-open-00..05.ppm` 和 `menu-close-00..05.ppm`，便于检查真实生产渲染的过渡帧。
界面替身检查每步菜单向显示服务提交一幅完整画面。
`tests/display_host/display_checks.c` 直接编译生产 `display_service.c`，仅替换 SDK 和 LVGL 外部接口，
检查 DMA 只读内部 RAM、逐段像素/尾段顺序、源帧字节序不变、完成前不覆盖、逐帧不分配、
初始化失败回收，以及发送错误、完成超时、迟到完成均不触发不安全重用或重新提交。
该测试也由 `scripts/check_ui.py` 执行，不参与固件构建。
这些测试不能模拟真实 LCD 扫描、SPI DMA 或 PSRAM 带宽，完整帧预览不能证明实屏无撕裂。
`tests/ui_animation_checks.c` 检查 229 个真实图像帧、RGB565 颜色、元信息过滤、
输出边界及损坏资源拒绝；帧图可组合成 GIF 用于视觉检查。

编译：在本工程 ESP-IDF 6.1 环境执行 `idf.py build`，检查两个 3 MiB OTA 分区的空间。
新增 `ui_assets` 数据分区位于 0x800000，容量 1MiB，不移动已有 NVS/模型/应用分区。
正常 `idf.py flash` 包含分区表和 `ui_assets.bin`；首次升级不能只执行 `app-flash`。
无需执行 `erase-flash`。以后仅应用 OTA 可复用兼容的资源包；本轮没有增加资源 OTA 更新器。
本轮不自动烧录。实板验收：

1. 冷启动确认屏幕方向、颜色、中文及背光；点击位置和按钮背景一致。
2. 首页上滑、菜单下滑各重复 10 次；确认移动方向与手势一致、停稳后点击位置正确，不能误触发对话。
   过渡中快速点击按钮或首页应被忽略；进入配网时不能停留在半屏菜单。
   启动应打印 `internal DMA=14400 bytes, direct PSRAM DMA off`，不应再有 DMA 欠载或 LCD 传输错误；
   待机和回答播放中分别检查分块错位是否改善，并重复冷启动确认不花屏、不停帧。
3. 播放中调音量/亮度，确认音频不中断；调节后等 2 秒重启，确认设置恢复。
4. 首页触屏唤醒和播放中触屏打断多轮，确认预录音补传、连续对话、60 秒待机。
   聆听中轻触应手动回到待机；播放中轻触一次进入聆听画面，再轻触应回到待机，
   即使取消确认尚未到达也不应被迟到事件重新唤起。随后轻触或说唤醒词应能开始新对话。
5. 菜单进入配网、退出、重新进入，提交新网络并确认名称更新；BOOT 长按仍有效。
6. 网络断开和重连时界面显示正确；观察音频欠载、内部堆余量、看门狗和任务栈水位。

构建与策略测试不能代替实板显示、触摸、音质和长期稳定性验证。
